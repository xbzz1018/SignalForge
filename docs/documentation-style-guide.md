# 文档约定

SignalForge 的文档分为项目展示、技术设计和操作资料。每篇只承担明确职责，优先更新已有内容，避免在多处重复维护同一套说明。

## 内容分工

| 位置 | 负责什么 |
| --- | --- |
| 根 README | 产品用途、实际结果、核心实现与入口 |
| 项目案例 | 一个任务如何交付，以及关键工程取舍 |
| 架构及专题文档 | 当前机制、接口、数据口径与边界 |
| quick-start / runbook | 可执行步骤、成功条件与故障定位 |
| learning | 需要背景知识的开发说明 |
| validation-status / evidence | 验证环境、结果、失败历史与可追溯来源 |

先写具体行为，再解释必要原因。比较项用表格，顺序步骤用列表；只有涉及多组件或状态变化时才画流程图。配置与命令放到对应操作文档，不占据项目首页。

## 截图与证据

- 产品展示只使用实际运行截图。采集前检查 API、资源请求、浏览器异常和对应任务结果。
- 不展示重复失败任务、过时执行器、错误覆盖层或尚未就绪的页面。排障案例若需要失败截图，必须在标题和图注中明确说明。
- 图表中的亏损、回撤或高风险属于业务结果，不应为了展示改成盈利或低风险。
- 可以裁切完整的内容区域，必须标注“节选”并保留原图哈希、尺寸、裁切坐标与对应运行记录；不能修改状态或图中数据。
- 同一张截图只在一个主要位置展示，其他文档链接引用。优先使用可维护的 Mermaid 解释流程，概念图不能当作产品截图或验收证据。
- 截图存放于 `docs/assets/`，来源摘要放在 `docs/evidence/`。历史证据保留原始身份，不随品牌修改。

## 与代码保持一致

| 变更 | 同步位置 |
| --- | --- |
| 接口或权限 | API 总览、认证专题、相关使用说明 |
| 参数或数据口径 | 行情数据源、研究正确性、数据字典 |
| 配置或运行进程 | 配置指南、基础设施、运行手册 |
| Skills 或产物合同 | Skills 治理、工作空间契约 |
| 验证口径 | 评测指南、验证记录与来源摘要 |

使用具体日期和代码路径；不提交密钥、个人路径或未脱敏日志。测试通过与生产验收分别记录，有限样本不写成稳定成功率。提交前运行 `npm run check:docs` 并核对图片及流程图。
